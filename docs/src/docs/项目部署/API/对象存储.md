# 对象存储：OCI 与腾讯 COS

ThriveX 一期默认使用本地存储；只有需要对象存储时才将 `STORAGE_PROVIDER` 设为 `s3`。后端通过 S3 兼容协议接入 Oracle Cloud Infrastructure（OCI）和腾讯云 COS，不在数据库、控制端或前端保存任何存储密钥。

> 图片必须能被访客直接读取。当前版本不生成签名 URL，因此请为图片所在 bucket 或指定前缀配置公开读，或提供可公开访问的 CDN 域名。

## 通用环境变量

以下变量只由后端读取。`STORAGE_S3_ACCESS_KEY` 与 `STORAGE_S3_SECRET_KEY` 应通过部署平台的 Secret 或环境变量注入，绝不提交到 Git、SQL 或前端构建产物。

```env
STORAGE_PROVIDER=s3
STORAGE_S3_ENDPOINT=https://s3.example.com
STORAGE_S3_REGION=your-region
STORAGE_S3_BUCKET=your-bucket
STORAGE_S3_PREFIX=uploads
STORAGE_S3_ACCESS_KEY=replace-with-access-key
STORAGE_S3_SECRET_KEY=replace-with-secret-key
STORAGE_S3_PUBLIC_URL=https://images.example.com
STORAGE_S3_PATH_STYLE=false
```

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `STORAGE_PROVIDER` | 是 | 填 `s3`；未设置时默认使用 `local`。 |
| `STORAGE_S3_ENDPOINT` | 是 | S3 兼容 API 的 HTTPS endpoint，必须与 bucket 所在地域一致。 |
| `STORAGE_S3_REGION` | 是 | 云厂商的地域标识，不是中文地域名。 |
| `STORAGE_S3_BUCKET` | 是 | Bucket 名称。 |
| `STORAGE_S3_PREFIX` | 否 | 将 ThriveX 文件限制在 bucket 的某个前缀，如 `uploads`；不加首尾 `/`。 |
| `STORAGE_S3_ACCESS_KEY` | 是 | S3 兼容访问密钥。 |
| `STORAGE_S3_SECRET_KEY` | 是 | S3 兼容访问密钥的 secret。 |
| `STORAGE_S3_PUBLIC_URL` | 建议 | 公开图片根 URL。设置后程序在其后拼接 prefix 和对象 key；常用于 CDN 或 COS 的 bucket 域名。 |
| `STORAGE_S3_PATH_STYLE` | 是 | `true` 为 `endpoint/bucket/key`，`false` 为 virtual-hosted style。 |

`PREFIX` 只影响 bucket 内对象位置，不会出现在后台传递的相对 key 中。例如 prefix 为 `uploads` 时，业务 key `article/cover.webp` 实际保存为 `uploads/article/cover.webp`。

## Oracle Cloud Infrastructure（OCI）

1. 创建或选择 Object Storage bucket，并为运行 ThriveX 的用户授予该 bucket 的列举、读取、写入和删除对象权限。
2. 在 OCI 用户设置中创建 **Customer Secret Key**。这里需要的是 S3 兼容 API 的 Access Key/Secret Key，不是 OCI API signing key。
3. 在 Object Storage 页面取得 namespace、bucket 名和 region identifier。
4. 使用 path-style endpoint：`https://<namespace>.compat.objectstorage.<region>.oraclecloud.com`。

示例（请替换尖括号内容）：

```env
STORAGE_PROVIDER=s3
STORAGE_S3_ENDPOINT=https://<namespace>.compat.objectstorage.<region>.oraclecloud.com
STORAGE_S3_REGION=<region>
STORAGE_S3_BUCKET=<bucket>
STORAGE_S3_PREFIX=uploads
STORAGE_S3_ACCESS_KEY=<oci-customer-secret-access-key>
STORAGE_S3_SECRET_KEY=<oci-customer-secret-key>
STORAGE_S3_PATH_STYLE=true
# 若已绑定 CDN 或自定义公开域名，填写其根地址；否则留空即可。
STORAGE_S3_PUBLIC_URL=
```

OCI 的 path-style URL 由 `endpoint/bucket/key` 组成，因此本项目的 `PATH_STYLE` 必须为 `true`。OCI 也支持 virtual-hosted style，但需要使用 `vhcompat` endpoint 和满足 bucket 名命名、作用域要求；除非明确需要，否则不要混用两种模式。详见 OCI 的 [S3 兼容 API 说明](https://docs.oracle.com/en-us/iaas/Content/Object/Tasks/s3compatibleapi.htm) 与 [寻址方式说明](https://docs.oracle.com/en-us/iaas/Content/Object/s3-virtual-style.htm)。

## 腾讯云 COS

1. 创建 COS bucket，记录 bucket 名称（通常包含 AppId，例如 `thrivex-1250000000`）和地域，如 `ap-guangzhou`。
2. 为专用子账号创建 SecretId/SecretKey，并按最小权限授予该 bucket 的 `List`、`Get`、`Put`、`Delete` 对象权限。
3. 使用 endpoint `https://cos.<region>.myqcloud.com`，不要把 bucket 名加到 `STORAGE_S3_ENDPOINT` 中。
4. 为图片设置公开读，并将 bucket 的公开访问域名或 CDN 域名填入 `STORAGE_S3_PUBLIC_URL`。

示例：

```env
STORAGE_PROVIDER=s3
STORAGE_S3_ENDPOINT=https://cos.ap-guangzhou.myqcloud.com
STORAGE_S3_REGION=ap-guangzhou
STORAGE_S3_BUCKET=thrivex-1250000000
STORAGE_S3_PREFIX=uploads
STORAGE_S3_ACCESS_KEY=<cos-secret-id>
STORAGE_S3_SECRET_KEY=<cos-secret-key>
STORAGE_S3_PUBLIC_URL=https://thrivex-1250000000.cos.ap-guangzhou.myqcloud.com
STORAGE_S3_PATH_STYLE=false
```

腾讯云 COS 的新 bucket 使用 virtual-hosted style；因此保持 `STORAGE_S3_PATH_STYLE=false`。如果是旧 bucket 且只能使用 path-style，才改为 `true`，并重新执行下文验收。腾讯云官方的 [S3 兼容配置说明](https://intl.cloud.tencent.com/document/product/436/34688) 和 [AWS Java SDK 接入说明](https://intl.cloud.tencent.com/document/product/436/32537) 可用于核对地域、endpoint 和寻址方式。

## 部署与验收

1. 将变量注入后端进程后重启服务。不要只写入浏览器配置或后台第三方配置表。
2. 以管理员身份调用 `POST /file/storage/test`。成功时返回 `200` 和“存储连接测试成功”。该接口会在配置的 prefix 下创建随机 `.thrivex-health/` 对象，读取元信息、列举后删除；不会返回密钥。
3. 在文件系统中创建一个目录、上传一张图片，确认列表、详情和目录树均显示该文件。
4. 用无痕窗口打开上传结果的公开 URL，确认匿名访客可读取图片。
5. 重命名目录，确认图片 URL 与对象位置同时更新；删除图片后删除空目录。

常见失败原因：

| 返回提示 | 检查项 |
| --- | --- |
| `S3 配置缺少字段` | 缺少 endpoint、region、bucket 或任一密钥环境变量。 |
| `S3 凭据无效或缺少 bucket 访问权限` | 使用了错误密钥，或子账号缺少 bucket 权限。 |
| `S3 bucket 不存在或 endpoint 配置错误` | bucket 名、namespace、region 或 endpoint 不匹配。 |
| `S3 endpoint 无法连接` | HTTPS、DNS、出网策略、防火墙或 region 配置有误。 |
| 图片上传成功但浏览器打不开 | bucket/prefix 未公开读，或 `STORAGE_S3_PUBLIC_URL` 填错。 |

根目录 Compose 已将这些变量显式传入 `server` 容器；完整的首次启动、升级与备份恢复流程见 [Docker Compose 部署](../Compose)。
